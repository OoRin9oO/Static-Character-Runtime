# 有限主题讨论与回复播放

## 编辑器使用

- 主题讨论轮数 1–6；一轮为所选 1–3 位角色各发言一次。主题入口要求至少两位角色，最多 18 次回复；普通评论只执行一轮。
- 入队时固定轮数与人数；执行期间修改这些选项只影响之后发送的话题。暂停或切换场景中止后续发言。
- 每轮重新开放发言资格。首轮优先回应观众点名，后续参考上一位角色的点名，并按最近发言顺序公平分配。
- 提示中包含主题、轮次、最近三条发言和在场角色；末轮最后一位得到收束提示。不是长期记忆，也不保证模型完全遵从。
- 默认最多三个动作，可调整为 1–6；模型可返回更少动作。只允许当前角色已有的状态。
- 文本阶段按照字数和展示语速估算总时长，2.5–60 秒；动作时长按比例映射到总时长。下一位等待展示完成，再等待设置的间隔。

## 未来 TTS 对接约定（尚未接入语音合成或音频播放）

编辑器为播放控制端，OBS 页面只接收同一份时间线，避免两个窗口重复发声。

1. 监听编辑器窗口的 `scr:reply-ready` 事件。`event.detail` 包含 `id`（每句唯一）、`sceneId`、`instanceId`、`text`、`estimatedDurationMs`。
2. 音频就绪后调用 `window.staticCharacterRuntime.reportReplyPlayback({ id, durationMs, positionMs, paused, ended })`。使用真实音频的 `duration`、`currentTime`（转为毫秒）；不要把生成耗时当作播放时长。
3. `playing`、`pause`、`waiting`、`seeked`、`timeupdate` 时同步进度。缓冲或暂停报告 `paused: true`。暂停期间也需定期报告；15 秒无更新将结束该句，防止失联的播放器卡住讨论。
4. `ended` 或播放失败时报告 `ended: true`，停止动效并释放发言队列。当前时长支持 250–120000 毫秒、正常 1 倍速播放。
5. 监听 `scr:reply-stop`，停止 `event.detail.ids` 中对应的音频；收到新句时避免旧音频继续播放。过期或其他场景的 ID 返回 `false`，不能重新启动旧回复。

报告成功返回 `true`。播放信息只保存在运行内存和直播快照里，不改角色包、基础姿态或永久场景坐标。真实 TTS 接入时仍需实现合成排队、音频加载、播放器和声音输出；这个接口本身不会发声。
