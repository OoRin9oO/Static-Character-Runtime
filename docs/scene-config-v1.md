# 场景配置 V1 草案

## 设计边界

- 本地编辑器管理角色实例、位置、层级、初始状态和互动规则。
- 最终背景、直播画布尺寸、OBS 场景与转场由用户在 OBS 中设置。
- 坐标使用 OBS 浏览器源可视区域内的归一化值：左上角 `(0, 0)`，右下角 `(1, 1)`。
- 场景引用角色包，不复制角色图片。同一角色包在一个场景中只允许出现一个实例；多个不同角色可以同框。
- 每个实例拥有独立的实例 ID、展示参数、模型引用和运行状态。
- V1 先用于本地编辑与预览，不连接直播平台、不自动发言。

## 数量限制建议

- 默认每个场景最多 6 个启用中的实例。
- 同一个角色包在同一个场景中最多出现 1 次。
- 场景总数限制可在编辑器的本地设置中调整，硬上限为 30。
- 达到上限时，编辑器阻止添加并说明原因，不自动删除或隐藏已有实例。
- 限制只作用于编辑器生成/保存的场景；配置加载时也需校验，超限配置标记为无效并提示用户修正。
- 上限作为本地编辑器设置暴露，用户可以自行调整。默认值为 6/2；减少上限时不自动删除场景中已有实例，而是提示超限并要求用户处理后才能新增/保存。

这些是防止编辑器配置失控的保守默认值，不代表所有系统的性能保证。实际可承载数量还受图片尺寸、透明像素、浏览器和 OBS 资源影响。

## 场景字段

```json
{
  "schemaVersion": 1,
  "id": "talk-show",
  "name": "聊天场景",
  "characters": [
    {
      "instanceId": "host-main",
      "characterId": "github-girl",
      "displayName": "GitHub娘-1",
      "enabled": true,
      "transform": { "x": 0.28, "y": 0.92, "scale": 0.8, "zIndex": 1 },
      "initialState": "idle",
      "model": { "provider": "bigmodel", "modelId": "glm-5.3-flash" }
    },
    {
      "instanceId": "host-guest",
      "characterId": "deepdeep",
      "displayName": "DeepDeep",
      "enabled": true,
      "transform": { "x": 0.72, "y": 0.92, "scale": 0.8, "zIndex": 2 },
      "initialState": "idle"
    }
  ],
  "interaction": {
    "mode": "manual",
    "turnOrder": ["host-main", "host-guest"],
    "maxParticipantsPerTurn": 2,
    "minReplyIntervalMs": 1500
  },
  "events": [],
  "metadata": { "notes": "背景和画布由 OBS 管理" }
}
```

## 字段说明

| 字段 | 必需 | 规则 |
|---|---|---|
| `schemaVersion` | 是 | 场景格式版本，当前为 `1` |
| `id` | 是 | 场景稳定 ID |
| `name` | 是 | 编辑器显示名称 |
| `characters` | 是 | 场景角色实例列表；`instanceId` 必须唯一 |
| `characters[].characterId` | 是 | 引用已登记角色包 ID |
| `characters[].displayName` | 是 | 对话、日志和编辑器使用的场景内唯一名称 |
| `characters[].enabled` | 是 | 控制是否加入当前场景预览/输出 |
| `characters[].transform.x/y` | 是 | 0 到 1 的相对坐标；`x/y` 表示立绘中心位置 |
| `characters[].transform.scale` | 是 | 正数缩放比例，需设合理上下限 |
| `characters[].transform.zIndex` | 是 | 非负整数，越大越靠前 |
| `characters[].initialState` | 否 | 必须属于引用角色包中的状态；缺省时用角色默认状态 |
| `characters[].model` | 否 | 模型供应商与模型 ID 引用；不得保存 API Key |
| `interaction.mode` | 是 | V1 仅 `manual`；未来再扩展轮流对话等模式 |
| `interaction.turnOrder` | 否 | 按 `instanceId` 指定候选发言顺序 |
| `interaction.maxParticipantsPerTurn` | 否 | 单次互动最多参与角色数 |
| `interaction.minReplyIntervalMs` | 否 | 限制连续互动频率 |
| `events` | 是 | V1 可为空；未来存储直播事件到目标角色/动作的规则 |
| `metadata` | 否 | 备注等非运行字段 |

## 编辑器功能顺序

1. 场景列表：新建、重命名、复制、删除、选择；本地保存和导入/导出 JSON。
2. 角色实例：从已登记角色包添加、移除、启用/隐藏；每个角色每场景唯一，使用唯一 `instanceId`。
3. 布局预览：拖动立绘中心移动，数字框/方向键用于细调，支持调整缩放和图层顺序；使用相对坐标，不设置固定背景。
4. 实例面板：独立设置初始姿态、快捷动作、当前状态和模型引用。
5. 互动测试：手动触发指定实例动作；V1 用模拟轮次检查发言顺序，不请求模型。
6. 校验与恢复：角色包缺失、状态不存在、ID 重复、实例超限时显示具体错误；自动保存并支持撤销/恢复。
7. 后续阶段：平台事件规则、B站连接器、队列和自动对话；在安全规则、限频和人工暂停控制验收后再启用。

## 待逐步确认的约束

- 单场景默认最多 6 个启用实例；同角色包每场景一个实例。
- `transform.x/y` 使用立绘中心锚点。
- 场景配置与素材角色包分离；场景文件只记录角色 ID 与实例设置。
- 模型配置只存非敏感引用；密钥仍由本机运行环境管理。
- 互动 V1 默认手动测试，自动轮流对话留到独立阶段。
- 用户可以调整每场景启用实例总数；每个角色包在场景中只出现一次。角色名作为实例默认显示名并确保场景内唯一。

## 角色素材与动作编辑建议

- 角色素材支持导入 ZIP。导入时检查压缩包路径、文件数量和解压后总大小；拒绝绝对路径、`..` 路径穿越、可执行文件及嵌套压缩包。先预览识别结果，由用户确认目标角色目录和分区后再解压。
- 建议角色包目录采用 `characters/<character-id>/Basic/`、`Emotion/`、`Interact/`、`Special/`。分区名大小写不敏感，并可在包格式中声明自定义分区；兼容缺少分类目录的旧清单。
- 建议角色状态图片统一画布尺寸、分辨率并使用透明背景，便于并排编排；但这不是导入要求。尺寸、格式或背景不一致时仍可使用，编辑器显示尺寸/透明度提示并允许逐状态缩放、锚点和偏移校准。
- 图片扩展名与实际格式需要校验。可支持浏览器能显示的 PNG、JPEG、WebP、GIF、AVIF 等；JPEG 无透明通道，应提示用户它会显示为不透明矩形。
- 导入新图片后，编辑器询问角色包和分类目录；状态显示名称默认取文件名，可在界面改名。
- 动作名称只写入角色清单的 `label` 字段，不强制重命名图片文件。这样既支持界面编辑，也避免因文件重命名破坏引用。提供“同时重命名图片文件”的显式操作时，必须原子更新文件与清单引用。
- 手动改 JSON/文件夹属于外部修改，页面需刷新后重新读取；浏览器可能缓存图片，提供硬刷新提示或使用文件版本参数避免旧图。
- ZIP 与拖入文件都走本地服务器受限写入接口，写入范围只能在项目 `characters/` 目录内，不能让浏览器任意写磁盘路径。
