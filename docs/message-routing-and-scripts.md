# 弹幕分流和剧本初版

## 评论处理

“自动识别”在模拟模式使用本地规则；AI 模式使用当前全局选择的模型，额外发送一次分类请求。模型只在个人回复、共同讨论中选择，不能直接执行动作。失败时界面显示回退来源，按本地规则继续；仍由角色自己的回复模型处理实际问题。

也可手动指定个人回复或共同讨论。“开始主题讨论”按钮始终使用讨论模式。讨论沿用当前轮数（最多六轮）和人数（至少两位、最多三位）。只有一位启用角色时降为个人回复。

自动分配识别场景名称、角色包显示名称和角色包 ID；按文本先后匹配。明确的 `@角色名` 在轮流模式下也优先。其他情况下轮流模式不按普通名称分配；重名别名不做猜测。界面显示实际选择的首位角色。

## 剧本

- 支持 UTF-8 JSON、TXT、Markdown；仅存于浏览器本次会话，刷新后重新导入。
- TXT/Markdown 每行 `角色名：台词`，空行和 `#` 开头的标题忽略。
- JSON 结构参见同目录 `script-example.json`。每行可附加 `state`，必须是匹配角色现有动作 ID；不填则使用默认姿态。
- 最多 200 条台词，每条最多 500 字。不执行脚本代码，不加载文件中的路径或网址。
- 导入只展示预览。每个剧本名称可以映射到一个启用的场景角色；未知或歧义名称必须手动选择。
- 点击确认播放后，暂停自动评论队列，等待当前请求退出，再校验全部角色与动作。校验成功后按顺序显示台词并播放动作，等待当前句展示结束后播放下一句。
- 停止或切换场景后不播放后续台词；再次播放从头开始。本版不支持断点续演和 AI 即兴改写。
- 使用同一字幕和动作快照同步到 OBS；当前没有语音，未来 TTS 可接已有 `scr:reply-ready` 和播放进度接口。

## 验收建议

1. “角色甲，你好”应为个人回复，“大家讨论一下这个话题”应为共同讨论。
2. 使用实际角色名称输入“@角色乙，请先聊聊”，检查首位显示为角色乙。
3. 导入示例，将角色甲和角色乙映射到现有场景角色，确认后播放；中途停止，确认后续台词不再出现。
4. 将 JSON 的 state 改为不存在的 ID，播放前应提示错误，不播放部分剧本。
